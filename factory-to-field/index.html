From a plant alarm to an approved action.

Agents that read refinery, oil-field and pump-maker data through one ontology, answer what is wrong, why, and who else is exposed, cite every finding, and never write to operations. Every action is a draft that a named person approves.

Watch the walkthroughOpen the case viewer

Six-minute walkthrough of the real application against simulated plant systems. Synthetic voice; captions are burned in.

One alarm, four layers

The example in the video: a drive-end vibration alarm on a refinery crude-unit pump. The agent traces it to a bearing lot that the pump maker released through an expedited change with its qualification test waived, and finds the same pattern in oil-field submersible pumps.

Sources

  • PI historian, SCADA, vibration spectra
  • SAP PM
  • OSDU, production planning
  • PLM, MES, quality (pump maker)

Ontology and graph

  • A position is a slot in the plant; a unit is the pump installed there, by date
  • Identity resolution links tags, serials and notifications
  • 109,591 facts with provenance

Agents

  • Read-only tools, also served over MCP
  • Playbook or model planner
  • Verifier checks every citation and quoted number

People

  • Drafts: notification, reservation, claim, 8D, operator request
  • Approved by a named person in the right role
  • Released with who approved

Run the live console

The live console needs the Python backend, so it runs on your machine rather than on this static page.

git clone https://github.com/kvinayakpai/domain-explorer
cd domain-explorer
pip install -r factory_to_field/requirements.txt
python -m factory_to_field.ui.live_app --port 8800   # builds the world and graph on first run
python -m factory_to_field.demo                       # end-to-end command-line demo

Limits

Read this before relying on it.
  • All data and systems are simulated. The simulators are my interpretation of each system's API, not vendor-certified.
  • The planner is playbook-based; the optional model planner has not been run against a live model.
  • The verifier checks that citations and numbers trace to the tool log, not every inference.
  • Not yet built: connectors to real SAP, PI, OSDU and PLM/MES, a review workflow for the identity queue, an identity provider for approvers.
